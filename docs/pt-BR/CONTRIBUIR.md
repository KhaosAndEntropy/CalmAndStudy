# Como eu convido você a contribuir

Eu aceito melhorias educativas, correções, acessibilidade, segurança, desempenho, documentação e traduções. Prefiro mudanças pequenas que expliquem o problema e possam ser revisadas com clareza.

1. Confira as [regras de contribuição](../../CONTRIBUTING.md) e procure uma issue semelhante.
2. Para uma mudança maior, abra primeiro uma issue curta com o objetivo e o impacto esperado.
3. Crie uma branch a partir de `main` e envie um pull request pequeno.
4. Descreva como verificar a mudança e inclua testes quando alterar comportamento.
5. Aguarde revisão humana; nenhuma sugestão ou PR é publicado automaticamente.

Eu separo duas coisas na documentação: **decisões do criador**, que definem o propósito e os limites do projeto, e **recomendações de implementação**, que são escolhas técnicas revisáveis. Você pode propor uma alternativa técnica sem mudar o propósito editorial.

O código contribuído é distribuído sob MIT e textos originais aceitos sob CC BY 4.0. Terceiros mantêm os direitos e as licenças dos próprios materiais. Use um nome público ou pseudônimo e verifique o e-mail do Git antes de publicar: commits são registros públicos.
