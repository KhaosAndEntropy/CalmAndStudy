# How I welcome contributions

I welcome educational improvements, corrections, accessibility, security, performance, documentation, and translations. I prefer small changes that explain the problem and are easy to review.

1. Read the [contribution rules](../../CONTRIBUTING.md) and look for a related issue.
2. For a larger change, open a short issue first with its goal and expected impact.
3. Create a branch from `main` and submit a focused pull request.
4. Explain how to verify the change and include tests when behaviour changes.
5. Wait for human review; neither a suggestion nor a pull request is published automatically.

I distinguish **creator decisions**, which set the purpose and editorial limits, from **implementation recommendations**, which are technical choices that can be revisited. You may suggest another technical approach without changing the editorial purpose.

Contributed code is distributed under MIT and accepted original text under CC BY 4.0. Third parties retain rights and licenses to their materials. Use a public name or pseudonym and check your Git email before publishing: commits are public records.
