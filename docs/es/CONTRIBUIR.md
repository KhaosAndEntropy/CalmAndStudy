# Cómo invito a contribuir

Acepto mejoras educativas, correcciones, accesibilidad, seguridad, rendimiento, documentación y traducciones. Prefiero cambios pequeños que expliquen el problema y sean fáciles de revisar.

1. Lee las [reglas para contribuir](../../CONTRIBUTING.md) y busca una incidencia relacionada.
2. Para un cambio grande, abre primero una incidencia breve con el objetivo y el impacto esperado.
3. Crea una rama desde `main` y envía una solicitud de incorporación pequeña.
4. Explica cómo verificar el cambio e incluye pruebas cuando cambie el comportamiento.
5. Espera la revisión humana; ninguna sugerencia o solicitud se publica automáticamente.

Distingo **decisiones del creador**, que definen el propósito y los límites editoriales, de **recomendaciones de implementación**, que son opciones técnicas revisables. Puedes proponer otra opción técnica sin cambiar el propósito editorial.

El código aportado se distribuye bajo MIT y los textos originales aceptados bajo CC BY 4.0. Los terceros conservan los derechos y licencias de sus materiales. Usa un nombre público o seudónimo y revisa el correo de Git antes de publicar: los commits son públicos.
